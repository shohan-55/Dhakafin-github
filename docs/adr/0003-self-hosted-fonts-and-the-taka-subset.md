# ADR-003: Self-hosted fonts, and a 960-byte subset for the taka sign

- **Status:** Accepted
- **Date:** 2026-09-20
- **Phase:** 1 (DF-P1-004)
- **Deciders:** DhakaFin engineering
- **Supersedes:** —

## Context

The blueprint calls for Plus Jakarta Sans (UI), Space Grotesk (financial
figures), Hind Siliguri (Bengali) and JetBrains Mono (regulatory references),
with a **180 KB font budget**.

Two facts emerged during implementation, neither of which was visible when the
budget was written.

**First**, `next/font/google` makes the production build depend on
`fonts.gstatic.com` being reachable. In this environment it is not, so the build
simply failed. That is not a sandbox quirk — it is the same failure a CI runner
or a locked-down deploy host would hit.

**Second**, and more interesting: `৳` is **U+09F3**, inside the Bengali block,
but it appears constantly in *English* prose (`৳12.5 L`). No Latin font we ship
carries it. So the browser resolved it through the Bengali face and downloaded
the **entire 139 KB Bengali font to draw one currency symbol.** The budget gate
measured `230.4 KB / 180 KB — 128%` and failed the build.

## Decision

**Self-host** all four families as committed `.woff2` assets loaded through
`next/font/local`, with the Bengali face carrying an explicit `unicode-range` so
that Latin-only pages never fetch it.

For the taka sign specifically: the Bengali range is **split around the currency
signs** (`U+0980-09F1,U+09F4-09FE`, dropping `U+09F2-09F3` and `U+20B9`), and a
dedicated **960-byte** face covers exactly those three codepoints, positioned
before the Bengali fallback in every font stack.

`scripts/check-font-budget.mjs` reconstructs the browser's font-resolution
algorithm from the build output — `@font-face` ranges, the real `--df-font-*`
stacks, and the rendered codepoints of the home page — and fails CI if the total
exceeds `font.budgetKB`.

## Consequences

**Positive**

- **88.9 KB** on first load, 49% of budget. The Bengali faces are correctly
  skipped on an English page and correctly fetched on a Bengali one.
- The build is hermetic: no CDN outage, proxy or air-gapped runner can break it.
- No visitor IP is disclosed to a third party for a font request.
- Font files are versioned and reviewable, so a weight change is a diff.
- The taka sign is now a **typographic decision with its own asset** rather than
  an accident of Unicode block boundaries.

**Negative**

- **244 KB of binaries in the repository.** Justified for fonts specifically
  (they are assets, not build output), but it does mean clones are larger and
  binary diffs are unreviewable.
- Adding or updating a font is now a manual, two-step operation documented in
  `apps/web/app/fonts/README.md`. Someone who adds an `.woff2` without reading
  that file will not know about the budget gate.
- The subset is generated by `pyftsubset`, a **Python** tool, while everything
  else in the pipeline is Node. Regeneration therefore needs a second toolchain.
  Accepted because regeneration is rare and deliberate, not part of `npm run
  verify`.
- Two extra font files (960 bytes) and an extra family in four CSS stacks exist
  solely to serve three glyphs.

**Neutral**

- Bengali body weight 500 is not shipped. Hind Siliguri's 400/600 pair covers
  body and emphasis, and a third 72 KB file to render one eyebrow label is not a
  trade a measured budget allows.

## Alternatives considered

- **Keep `next/font/google`.** Rejected: it failed the build here, and would make
  every future build depend on a third party being up.
- **Let `৳` fall back to a system font.** Zero bytes, and rejected. Coverage is
  inconsistent across platforms (Nirmala UI / Bangla Sangam MN / Noto Sans
  Bengali), and a currency symbol rendering as tofu or as a mismatched shape on
  the largest number on the page is not compatible with the "zero design
  compromise" directive.
- **Accept the 139 KB Bengali download.** Rejected — the blueprint's performance
  directive is explicit that effects are subordinate to speed, and a currency
  sign is not an effect.
- **Raise `font.budgetKB` to 250.** Rejected. The budget is a performance
  contract; moving it to accommodate a 139 KB accident inverts its purpose.
- **Subset the full Bengali font down to the glyphs used on each page.** Would
  work, but it conflicts with the product's own requirement that Bengali content
  be *editable by Filament without a developer* — content that arrives after the
  build cannot be covered by a build-time subset.

## Review trigger

Revisit if a Bengali brand or legal face is added (a second 140 KB family would
break the budget), or if the currency subset is found to be missing a sign used
by cross-border trade content.
